# 实验一：Gazebo 仿真传感器安装、配置与故障诊断

## 一、基本信息

- 实验学时：3 学时
- 实验形式：3～4 人一组，Gazebo Classic 11 + ROS 2 Humble 纯仿真
- ROS 2 功能包：`experiment3`
- 工作空间：`~/experiment3_ws`
- 机器人模型：室内环境中的差速移动机器人
- 实验对象：相机、三维激光雷达、IMU

## 二、实验任务

在已有仿真机器人上完成传感器数据链路检查，并修复故障版本中的两个配置问题：

1. 查阅机器人 Xacro、Gazebo 插件和启动文件。
2. 建立仿真传感器台账。
3. 检查相机、点云和 IMU 话题是否存在。
4. 检查消息类型、发布频率、时间戳和 `frame_id`。
5. 检查传感器坐标系与机器人坐标系之间的 TF。
6. 使用 RViz 观察传感器数据与场景是否一致。
7. 启动双故障版本，定位并修复两个配置问题。
8. 重启仿真并完成修复后的复测。

本实验的重点不是编写复杂的 ROS 2 节点，而是根据话题、消息、TF 和 RViz 现象判断配置是否正确。

## 三、实验环境

- Ubuntu 22.04
- ROS 2 Humble
- Gazebo Classic 11
- RViz2
- `tf2_ros`、`tf2_tools`
- 课程工作空间：`~/experiment3_ws`

启动前执行：

```bash
source /opt/ros/humble/setup.bash
source ~/experiment3_ws/install/setup.bash
```

启动正常版本：

```bash
ros2 launch experiment3 sim.launch.py
```

打开 RViz 配置：

```bash
rviz2 -d ~/experiment3_ws/src/experiment3/config/experiment3.rviz
```

如果虚拟机图形显示卡顿，可使用软件渲染启动 Gazebo：

```bash
LIBGL_ALWAYS_SOFTWARE=1 \
ros2 launch experiment3 sim.launch.py
```

## 四、当前仿真接口

### 4.1 传感器话题

| 传感器 | 话题 | 消息类型 | 配置频率 |
|---|---|---|---:|
| 相机图像 | `/camera/depth_camera/image_raw` | `sensor_msgs/msg/Image` | 10 Hz |
| 相机信息 | `/camera/depth_camera/camera_info` | `sensor_msgs/msg/CameraInfo` | 10 Hz |
| 三维激光雷达 | `/mid360/points` | `sensor_msgs/msg/PointCloud2` | 10 Hz |
| IMU | `/imu/data` | `sensor_msgs/msg/Imu` | 100 Hz |

当前相机虽然在模型中命名为 `depth_camera`，但实际输出的是普通图像和相机信息，没有单独的深度图话题。本实验报告统一写“仿真相机”。

### 4.2 坐标系

| 对象 | 坐标系 |
|---|---|
| 里程计参考 | `odom` |
| 机器人基座 | `base_link` |
| 相机 | `camera_link` |
| 三维激光雷达 | `mid360_link` |
| IMU | `imu_link` |
| 万向轮 | `caster_link` |

正常版本的 TF 关系为：

```text
odom
└── base_link
    ├── camera_link
    ├── mid360_link
    ├── imu_link
    └── caster_link
```

### 6.4 检查话题和消息

筛选传感器话题：

```bash
ros2 topic list | grep -Ei \
  'camera|image|depth|imu|scan|point|lidar|laser|mid360'
```

检查相机：

```bash
ros2 topic info /camera/depth_camera/image_raw --verbose
ros2 topic hz /camera/depth_camera/image_raw
ros2 topic echo /camera/depth_camera/camera_info --once
```

检查三维点云：

```bash
ros2 topic info /mid360/points --verbose
ros2 topic hz /mid360/points
ros2 topic echo /mid360/points --once
```

检查 IMU：

```bash
ros2 topic info /imu/data --verbose
ros2 topic hz /imu/data
ros2 topic echo /imu/data --once
```

记录话题是否存在、发布者和订阅者数量、消息类型、时间戳是否递增、`frame_id` 是否正确，以及实测频率。虚拟机中 IMU 实测频率约 90～92 Hz，允许出现仿真调度波动。

### 6.5 检查 TF 坐标变换

```bash
ros2 run tf2_ros tf2_echo odom base_link
ros2 run tf2_ros tf2_echo base_link camera_link
ros2 run tf2_ros tf2_echo base_link mid360_link
ros2 run tf2_ros tf2_echo base_link imu_link
ros2 run tf2_tools view_frames
```

判断：`odom`、`base_link` 和三个传感器坐标系是否存在；坐标树是否连通、无环；平移量和旋转量是否与 Xacro 中的安装参数一致；变换方向是否能够解释。

正常版本中，IMU 安装变换应接近：

```text
translation: x=-0.15 m, y=0.00 m, z=0.34 m
rotation: 0 0 0
```

### 6.6 使用 RViz 观察数据

```bash
rviz2 -d ~/experiment3_ws/src/experiment3/config/experiment3.rviz
```

确认：

```text
Global Options -> Fixed Frame -> base_link
```

RViz 中应包含：

| 显示项 | 设置 |
|---|---|
| RobotModel | 默认 |
| TF | 显示坐标轴和坐标系名称 |
| PointCloud2 | `/mid360/points` |
| Image | `/camera/depth_camera/image_raw` |

检查机器人模型、TF 坐标轴、点云位置和方向、相机图像更新情况。保存正常版本的 RViz 截图。

### 6.7 启动双故障版本

关闭正常仿真后，启动故障版本：

```bash
source /opt/ros/humble/setup.bash
source ~/experiment3_ws/install/setup.bash

ros2 launch experiment3 sim_fault_double.launch.py
```

使用正常 RViz 配置观察：

```bash
rviz2 -d ~/experiment3_ws/src/experiment3/config/experiment3.rviz
```

记录故障现象，不要直接修改文件。至少完成以下检查：

```bash
ros2 topic list | grep -Ei 'mid360|point|lidar'
ros2 run tf2_tools view_frames
ros2 run tf2_ros tf2_echo odom base_link
ros2 run tf2_ros tf2_echo odom fault_base_link
```

故障版本的现象应包括：

- RViz 的 Fixed Frame 使用 `base_link` 时出现 TF 错误；
- TF 树中出现 `fault_base_link` 而不是正常的 `base_link`；
- `/mid360/points` 不存在，PointCloud2 显示错误或 0 个点；
- 相机和 IMU 话题仍可用于对比检查。

### 6.8 修复并复测

在故障版本中找到并修复两个配置问题。修复后：

1. 重新编译工作空间。
2. 完整关闭并重新启动仿真。
3. 重新打开 RViz 配置。
4. 重复话题、频率和 TF 检查。

```bash
cd ~/experiment3_ws

colcon build \
  --symlink-install \
  --packages-select experiment3

source /opt/ros/humble/setup.bash
source ~/experiment3_ws/install/setup.bash

ros2 launch experiment3 sim_fault_double.launch.py
```

复测命令：

```bash
ros2 topic list | grep mid360
ros2 topic hz /mid360/points
ros2 run tf2_ros tf2_echo odom base_link
ros2 run tf2_ros tf2_echo base_link mid360_link
```

修复后的验收结果：

```text
TF 树包含 odom -> base_link
/mid360/points 存在并持续发布
RViz Fixed Frame=base_link
PointCloud2 Status=Ok 且可以看到点云
```

提交修复前后 RViz 截图、命令输出或频率统计、修复参数和复测结论。
